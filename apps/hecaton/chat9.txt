● HECATON Multi-Agent Orchestration Workflow & Logic

  Core Concept

  HECATON (named after the hundred-handed giants of Greek mythology) is a production-ready multi-agent orchestration system
  that spawns multiple Claude Code CLI instances in parallel, each working in isolated git worktrees with their own tokens.

  Architecture Components

  1. Entry Points

  - Main Module (__main__.py): CLI interface with commands: run, benchmark, test
  - Enhanced CLI (hecaton_cli_enhanced.py): Production-ready orchestrator with optimizations
  - Supports both REAL mode (actual API calls) and MOCK mode (testing without API)

  2. Core Orchestration Flow

  User Task → Token Pool → Worktree Creation → Agent Spawn → Parallel Execution → Result Aggregation

  Step-by-step workflow:

  1. Task Reception
    - User provides task via CLI: python -m hecaton run "Build a REST API" --agents 5
    - Task complexity analyzed (SIMPLE/NORMAL/COMPLEX)
    - Agent types auto-selected or specified
  2. Resource Allocation
    - Token Pool: Round-robin rotation through 1-15 Claude tokens
    - Worktree Manager: Creates isolated git worktree per agent
    - Each agent gets unique branch: agent/{timestamp}/{type}/{id}
  3. Agent Configuration
    - Agent Registry: Manages specialized agent types (code, test, research, review, docs)
    - Command Factory: Builds optimized Claude CLI commands based on:
        - Task complexity
      - Agent profile (SPEED_DEMON, PRODUCTION, QUALITY_CHAMPION)
      - Model selection (sonnet for simple, opus for complex)
  4. Parallel Execution
    - RealClaudeSubprocessExecutor: Spawns actual Claude CLI subprocesses
    - Each subprocess runs with:
        - Dedicated token (via CLAUDE_CODE_TOKEN env var)
      - Isolated worktree directory
      - Specific prompt and configuration
    - Removes ANTHROPIC_API_KEY to prevent conflicts
  5. Process Management
    - Async subprocess creation with stdout/stderr capture
    - Debug logging optional (30% slower but comprehensive)
    - Session tracking with UUIDs
    - Performance monitoring
  6. Result Aggregation
    - Waits for all agents via asyncio.gather()
    - Collects outputs, errors, metrics
    - Generates summary reports

  Key Innovations

  Token Pool Management

  - Thread-safe rotation through multiple tokens
  - Usage statistics and health tracking
  - Secure hashing for safe logging
  - Supports config file or environment variables

  Worktree Isolation

  - Each agent works in separate git worktree
  - Prevents merge conflicts between parallel agents
  - Automatic cleanup after execution
  - Branch naming: agent/{timestamp}/{type}/{agent_id}

  Command Optimization

  - Dynamic command building based on task analysis
  - Profile selection:
    - SPEED_DEMON: Quick tasks, minimal tools
    - PRODUCTION: Balanced performance
    - QUALITY_CHAMPION: Complex tasks, all tools
  - Long prompts handled via file reference (@file.txt)

  Debug & Monitoring

  - Comprehensive logging at multiple levels
  - Session tracking with unique IDs
  - Performance metrics collection
  - Debug mode available (slower but detailed)

  Execution Modes

  1. Simple Run: python -m hecaton run "task" --agents 2
  2. Mock Mode: python -m hecaton run "task" --mock (no API calls)
  3. Benchmark: python -m hecaton benchmark --iterations 3
  4. Self-test: python -m hecaton test
  5. Debug Mode: Set HECATON_DEBUG=true for detailed logs

  Scaling Pattern

  The system follows a phased scaling approach:
  - Phase 0: 2 agents (basic parallel)
  - Phase 1: 5 agents (SDLC team)
  - Phase 2: 10 agents (full orchestration)
  - Phase 3: 15 agents (maximum parallelism)

  Configuration Sources

  1. Tokens:
    - Environment: CLAUDE_CODE_TOKEN, CLAUDE_CODE_TOKEN1-15
    - Config file: config/claude_tokens.json
  2. Agent Types:
    - Loaded from .claude/agents/ definitions
    - Dynamic registration supported
  3. Workspace:
    - Worktrees in /tmp/hecaton_workspace/
    - Logs in /tmp/hecaton_{pid}.log

  Performance Optimizations

  - Parallel subprocess execution (not sequential)
  - Token rotation prevents rate limiting
  - Worktree isolation prevents conflicts
  - Command optimization reduces latency
  - Selective tool allocation per agent type
  - Debug mode optional (30% performance penalty)

  This architecture enables true parallel execution of multiple Claude instances, each working independently but coordinated
  toward a common goal, mimicking a team of specialized developers working on different aspects of the same project.

  - Location: src/hecaton/agents/claude_executor.py

  - Location: src/hecaton/execution/headless_executor.py
  - Role: Claims 3-20 seconds per task vs 15+ minutes with default config
