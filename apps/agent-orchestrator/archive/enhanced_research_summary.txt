PYTHON ERROR HANDLING BEST PRACTICES - TOP 3 KEY POINTS

1. BE SPECIFIC WITH EXCEPTION CATCHING
   - Always catch specific exception types (ValueError, KeyError, IOError) rather than broad Exception or bare except clauses
   - This prevents masking unexpected bugs and makes debugging easier
   - Use focused try blocks that isolate individual operations to pinpoint exact error sources
   - Example: try specific_operation() except ValueError as e: handle_value_error(e)

2. FOLLOW THE EAFP PRINCIPLE (EASIER TO ASK FORGIVENESS THAN PERMISSION)
   - Prefer try/except blocks over excessive pre-condition checks (LBYL - Look Before You Leap)
   - Let operations fail and handle exceptions rather than checking every possibility beforehand
   - This leads to cleaner, more Pythonic code that performs better in the common successful case
   - Example: Use try: dict[key] except KeyError rather than if key in dict: dict[key]

3. IMPLEMENT PROPER ERROR PROPAGATION AND CONTEXT
   - Let non-recoverable errors bubble up to appropriate handling levels
   - Add contextual information to exceptions using add_note() (Python 3.11+) or custom exception messages
   - Implement strategic logging with appropriate levels and contextual details for debugging
   - Use a top-level exception handler in applications to gracefully handle any unhandled exceptions
   - Example: Log errors with context, re-raise when necessary, and handle at the appropriate application layer
