● Complete System Architecture - What It Actually Does

  System Overview

  The system is a multi-project knowledge management and intelligent code analysis platform that provides:
  1. Persistent memory across Claude sessions via Neo4j + Qdrant
  2. Project-scoped knowledge isolation to prevent cross-contamination
  3. Dynamic instruction retrieval replacing static configuration files
  4. Semantic search for intelligent file selection and context retrieval
  5. Code complexity analysis and architectural understanding

  Core Components and Step-by-Step Flow

  1. Knowledge Base (KB) Infrastructure

  - Neo4j: Graph database storing knowledge nodes with relationships
    - Knowledge nodes have: id, content, knowledge_type, project_path, metrics, created_at
    - Project nodes have: path, name, type (root/app/standalone)
    - Relationships: Project -[:HAS_KNOWLEDGE]-> Knowledge
  - Qdrant: Vector database for semantic search
    - Collections: knowledge_vectors (2888 vectors), instructions (12 vectors), monitoring_vectors (0)
    - 384-dimension embeddings using sentence-transformers/all-MiniLM-L6-v2
  - Knowledge MCP Tool (/home/opsvi/master_root/libs/opsvi_mcp/servers/knowledge.py):
    - knowledge_store(): Store content with auto-embedding generation
    - knowledge_query(): Query by type, search text, or recency
    - knowledge_update(): Update confidence scores based on usage
    - knowledge_supersede(): Replace outdated knowledge

  2. Project Scoping System

  Purpose: Isolate knowledge by project to prevent queries in one project from returning results from another.

  How it works:
  1. Each knowledge entry has a project_path field
  2. Projects are registered as nodes in Neo4j
  3. Queries filter by project path:
  MATCH (p:Project {path: $project_path})-[:HAS_KNOWLEDGE]->(k:Knowledge)
  4. Hierarchical scoping levels: FILE → MODULE → APP → APPS/LIBS → PROJECT → GLOBAL

  3. Dynamic Instructions System

  Purpose: Replace static CLAUDE.md with dynamic, context-aware instructions from KB.

  Step-by-step agent startup:
  1. Agent starts in working directory (e.g., /home/opsvi/master_root/apps/ACCF)
  2. Queries KB for GLOBAL_INSTRUCTIONS (applies to all agents)
  3. Queries KB for PROJECT_INSTRUCTIONS matching working path
  4. Queries KB for APP_INSTRUCTIONS specific to current app
  5. Performs semantic search for task-relevant instructions
  6. Combines all instructions in priority order: APP > PROJECT > GLOBAL

  4. ACCF Integration

  Location: /home/opsvi/master_root/apps/ACCF (migrated from /home/opsvi/ACCF)

  KB-Powered Gatekeeper (kb_gatekeeper.py):
  1. Receives prompt from consult request
  2. Generates embedding for the prompt
  3. Searches Qdrant for relevant code/files
  4. Extracts file paths from search results
  5. Returns RequestCard with intelligent file selection
  6. Falls back to mock data if KB unavailable

  Batch Ingestion (batch_ingest_kb_v2.py):
  1. Scans project files
  2. Extracts metadata (language, size, complexity)
  3. Generates embeddings for each file
  4. Stores in Neo4j with project scoping
  5. Indexes in Qdrant for vector search

  5. Project Intelligence Integration

  Purpose: Analyze code complexity, dependencies, and architecture.

  Analysis Flow:
  1. Scans codebase using AST parsing
  2. Calculates metrics:
    - Max nesting depth
    - Number of classes/functions
    - Lines of code
    - Cyclomatic complexity
  3. Stores analysis in KB with CODE_ANALYSIS type
  4. Links to project: Project -[:HAS_ANALYSIS]-> Knowledge
  5. Enables queries like "find most complex function in project X"
